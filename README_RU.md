# Velvet Poker 0.3 — Cloudflare и хост на телефоне

Android-приложение для техасского холдема на 2–4 человека из разных мест.

**Телефон хоста ведёт игру:** тасует колоду, проверяет действия, считает банки и победителей, сохраняет партию. Другие телефоны передают ему команды. Внешний сервис связи маршрутизирует зашифрованные сообщения, выдаёт коды комнат и обслуживает профили/друзей.

Готовый файл: **Velvet_Poker_0.3_Cloudflare.apk**. Подпись совпадает с версиями 0.1 и 0.2: обновление можно устанавливать поверх неё без удаления приложения.

**Адрес уже встроен:** `https://velvet-poker.darkminecralll.workers.dev`.
На момент сборки там находилась заглушка Hello World. Для онлайн-игры владелец должен один раз загрузить серверный пакет из папки `cloudflare/`. Инструкция: `cloudflare/START_HERE_RU.md`; на Windows — `DEPLOY_WINDOWS.cmd`. Пакет не опубликован из этой среды, доступ к аккаунту Cloudflare не предоставлялся.

После установки сервиса все игроки просто указывают имя. Настройки адреса спрятаны в раскрывающийся пункт. Проверка готовности сервиса показывает понятную ошибку, если вместо API отвечает стартовая страница.

Новое в 0.3: защищённый WebSocket-транспорт, объединение повторных запросов и уведомления об изменениях; SQLite Durable Object для профилей/друзей/метаданных; установка на Workers Free; готовый адрес в APK. Существующий Python-сервис 0.2 также поддерживается через HTTPS.

Установка/запуск на физическом Android и реальных мобильных сетях пока не проверены. Сборка, подпись, игровая логика и локальная среда Cloudflare проверены; подробности в `VALIDATION_RU.md`.

## Что изменилось

| Функция | Где работает в 0.3 |
| --- | --- |
| Тасование и полная колода | Телефон хоста |
| Проверка ставок, порядок ходов | Телефон хоста |
| Выигрыш, олл-ин, побочные банки | Телефон хоста |
| Полное сохранение раздачи | Внутренняя память телефона хоста |
| Личные карты гостя | Только отдельный зашифрованный снимок для этого гостя |
| Коды комнат, профили, друзья | Общий сервис связи |
| Передача команд и снимков | Через WSS/HTTPS-ретранслятор, содержимое дополнительно зашифровано |

Это **не чистое прямое P2P** и не офлайн-режим. Используется внешний WSS/HTTPS-ретранслятор без входящих соединений на телефоне: такой способ не требует проброса портов у игроков. WebRTC/STUN/TURN в этой версии не используются.

## Как играть

1. Установить APK на телефоны Android 8.0 или новее. Обновить системный Android WebView, если он очень старый.
2. После установки пакета Cloudflare создать отдельные профили на телефонах. Адрес сервиса уже выбран; для другого сервера есть настройки подключения.
3. Хост нажимает «Создать стол», задаёт номиналы фишек, количества, блайнды и время хода.
4. Остальные заходят по коду комнаты или принимают приглашение друга.
5. Хост начинает раздачу и **держит приложение открытым**. Во время хостинга приложение удерживает экран включённым.
6. При сворачивании или выходе хоста сохраняется пауза. При сетевом обрыве гости обнаруживают отсутствие хоста по heartbeat — до примерно 8–10 секунд; после этого ставки блокируются.
7. Хост возвращается в ту же комнату на том же устройстве и нажимает «Продолжить игру» в меню стола. После разрыва связи игра не возобновляется автоматически.

Новые участники занимают места между раздачами. Уже игравшие могут вернуться во время раздачи. Профиль игрока и его стек не меняются из-за переподключения.

## Сохранения

- В Android полное сохранение и ключи каналов записываются во внутренние файлы приложения через `AtomicFile`.
- В браузерном тестовом клиенте аналогом является `localStorage`; это не облачная копия.
- После каждой принятой команды сначала сохраняется новое состояние, затем отправляется подтверждение. Повторная доставка той же команды не повторяет списание фишек.
- Во время восстановления незавершённая раздача ставится на паузу с теми же картами и остатком колоды.
- Два одновременно открытых окна одного хоста не получают управление одним столом. Сервис выдаёт lease сессии; дополнительно проверяется версия локальной записи.
- **Ключ профиля восстанавливает профиль и друзей, но не переносит локальное сохранение хозяина на другой телефон.** Не удаляйте приложение/его данные, если нужны сохранённые столы. Обновление APK поверх старого с той же подписью сохраняет данные.
- Экспорт/импорт сохранений и передача роли хоста другому телефону в 0.3 ещё не реализованы. В режиме хоста на телефоне старой кнопки передачи роли нет.
- Адрес сервиса является частью области хранения. Смена домена требует отдельного переноса локальных записей; простая смена адреса в настройках не переносит их автоматически.

Сервис связи хранит профили, дружбу, состав комнаты, открытые ключи и краткую сводку `hand/phase/paused`. Очереди и зашифрованные снимки находятся в памяти процесса. После перезапуска сервиса хост публикует состояние заново. Колода и полное состояние новой комнаты на сервис не отправляются.

Старый Python-движок сохранён только для совместимости с комнатами 0.1 и тестов сравнения. Все новые комнаты приложения 0.3 создаются с хостом на устройстве.

## Правила и интерфейс

- Безлимитный техасский холдем: две личные карты, флоп, тёрн, ривер.
- Чек / колл / ставка / рейз до общей суммы / пас / олл-ин.
- Минимальное повышение, короткие и последовательные олл-ины, повторное открытие торговли, побочные банки, возврат непокрытой ставки и раздел банка.
- Правильный порядок ходов вдвоём и переход к heads-up без повторного большого блайнда при выбывании дилера.
- Фиксированные блайнды, без анте, рейка и платёжных операций.
- Пять настраиваемых номиналов. По умолчанию 1 / 5 / 25 / 100 / 500, по десять фишек каждого вида: стартовый баланс 6310.
- Баланс хранится в целых единицах младшего номинала; размен автоматический. Первый номинал всегда 1 для точного раздела банка.
- Общий справочник комбинаций без определения вашей руки. Выигравшая комбинация объявляется только после вскрытия.
- Друзья по личному коду, заявки и приглашения. Приглашения видны в открытом приложении и действуют сутки; системных push-уведомлений нет.
- Хост может добавить фишки между раздачами. Тайм-аут участника: чек, если он разрешён, иначе пас.
- Четыре участника закреплены за сохранённым столом. Замена участника, удаление комнат и изменение номиналов уже созданного стола пока не добавлены.

Хост — доверенный участник дружеской игры: его устройство технически располагает полной колодой. Шифрование каналов не защищает от владельца модифицированного приложения хоста. Публичные ключи связываются с профилями через доверенный сервис связи; отдельной проверки отпечатков ключей пользователями нет.

## Запустить сервис связи локально

Нужен Python 3.11+. Внешние Python-пакеты не требуются.

```bash
cd velvet-poker
python3 -m server.app
```

Открыть `http://127.0.0.1:8080` в разных браузерных профилях на том же компьютере. Обычные вкладки одного профиля разделяют аккаунт и сохранение; это не разные игроки.

`127.0.0.1` на телефоне означает сам телефон. Для подключения телефонов из разных мест нужен общий HTTPS-адрес.

## Альтернативное размещение Python-сервиса

В проект включены Docker Compose и Caddy. Нужна машина/среда размещения с публичным доступом и доменом; приобретение или аренда не выполняются этим архивом.

1. Скопировать проект на хостинг с Docker Compose.
2. Скопировать `.env.example` в `.env`.
3. Задать домен: `DOMAIN=poker.example.com`, направить DNS на машину.
4. Открыть порты 80 и 443.
5. Выполнить:

```bash
docker compose up -d --build
```

Caddy обслуживает HTTPS. Проверка: `https://ваш-домен/health` должна вернуть `phone_host: true` и `protocol: 2`. Участники вводят `https://ваш-домен` в поле «Сервис связи».

Сервис не нужно ставить отдельно для каждого игрока или комнаты. Один экземпляр обслуживает личный клуб. Состояние аккаунтов сохраняется в volume `poker_data`; не используйте `docker compose down -v`, если нужно его сохранить. Для резервного копирования БД есть `server/backup.py` с SQLite backup API. Это копия профилей и метаданных, **не замена сохранениям на телефоне**.

Для этого небольшого клуба используется один процесс ретранслятора. Несколько параллельных экземпляров без общего хранилища очередей не поддерживаются. Python HTTP-сервис должен находиться за HTTPS-прокси, а не на открытом внешнем порту.

## Пересобрать APK

Поставляемый APK собран официальными Android Build Tools 35.0.0, API 35 и Java 17 скриптом `tools/build_apk.py`. APK v2/v3-подпись и выравнивание проверены.

```bash
python3 tools/build_apk.py \
  --build-tools /path/to/android-sdk/build-tools/35.0.0 \
  --android-jar /path/to/android-sdk/platforms/android-35/android.jar \
  --output Velvet_Poker_0.3_Cloudflare.apk
```

Также есть Gradle-проект и GitHub Actions workflow. Для локального Gradle: JDK 17, Gradle 8.11.1, SDK 35 / Build Tools 35.0.0, AGP 8.9.2.

```bash
gradle -p android assembleDebug lintDebug
```

Workflow `.github/workflows/android.yml` запускается вручную или после push в main/master, проверяет код и публикует артефакт APK. Он не запускался в этой сессии. Gradle Wrapper binary в архив не включён.

`android/debug.keystore` — намеренно включённый общий тестовый ключ с паролем `android`, чтобы личные пересборки можно было устанавливать поверх. Он не секретный и не подходит для публичного релиза. Для магазина приложений нужна отдельная закрытая подпись.

## Проверки

```bash
python3 -m unittest discover -s tests -v
node --test tests/engine.test.cjs tests/client.test.cjs
```

Node.js 24 LTS нужен для клиентских тестов и сравнения движков. `tests/browser.smoke.cjs` использует Playwright и настоящий Chromium; путь к браузеру можно передать в `CHROMIUM_PATH`.

Что подтверждено и что ещё не проверено — в `VALIDATION_RU.md`.

Проверки Cloudflare выполняются из его папки после `npm ci`:

```bash
cd cloudflare
npx wrangler deploy --dry-run --outdir build
npm test
```

`cloudflare/test/browser.smoke.mjs` — отдельная проверка интерфейса на четырёх Chromium-клиентах против локального Miniflare. Требует Playwright и `CHROMIUM_PATH`. Публичный сервис этими тестами не заменяется.

## Основные файлы

- `cloudflare/` — Worker, SQLite Durable Object, WebSocket API и установочные скрипты.
- `android/app/src/main/assets/transport.js` — соединение, авторизация, кэширование и переподключение.
- `android/app/src/main/assets/engine.js` — игровые правила, исполняемые устройством хоста.
- `android/app/src/main/assets/phone.js` — локальные сохранения, шифрование, подтверждения и восстановление соединения.
- `android/app/src/main/assets/app.js`, `style.css` — интерфейс.
- `android/app/src/main/java/club/velvet/poker/MainActivity.java` — Android, AtomicFile и управление экраном.
- `server/phone_relay.py` — маршрутизация зашифрованных пакетов и lease хоста.
- `server/app.py` — HTTPS-прокси-совместимый API, аккаунты и друзья.
- `server/poker.py` — совместимость с 0.1 и эталон для сравнения правил.
- `tests/` — игровые, транспортные и браузерные проверки.
